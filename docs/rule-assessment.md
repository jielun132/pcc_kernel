# 执行计划规则预判（0.1.5）

规则预判回答“从已采集的计划变化能否推断一个方向”。输入是同一 SQL 样例、相同参数下的普通 EXPLAIN，不执行 EXPLAIN ANALYZE，不证明实测耗时、生产性能或版本因果关系。

## 在报告中使用

报告打开时展示推荐规则的默认判断。展开“选择规则与阈值”，勾选后点击“按所选规则重新判断”。每次处理全部已确认差异 SQL；搜索、分页、分组、暂缓查看的库只影响浏览。

修改规则或阈值后，页面标记“当前展示上次判断结果”并暂停导出；点击重判才应用。全不选时，全部差异保持待复核。JSON/CSV 导出包含所选规则、阈值、规则版本和指纹、报告指纹、每条 SQL 的结论、命中证据及未覆盖差异。页面内修改不会写回原始归档，重新打开 HTML 恢复生成时的默认结果。

原有三类统计和退出码不变：计划一致项与无法比对项不参与规则预判。相似计划分组不会继承或传播结论。存在非阻断的上下文差异时，保留警告，不能将结论直接归因于版本。

## 判定方式

每个候选命中记录规则 ID、方向、原始差异序号、旧新节点、前提和数值证据。只有覆盖了全部差异才允许自动分类：

| 证据组合 | 结论 |
|---|---|
| 只有变优方向，可同时含等价证据 | 变优 |
| 只有变差方向，可同时含等价证据 | 变差 |
| 全部差异均有等价证明，或共同工作量模型处于明确的容差范围内 | 基本等价 |
| 未覆盖、缺少前提、阈值未满足、语义不完整或正反方向冲突 | 待复核 |

不把没有命中当作等价，也不把计划一致说成实测性能相同。结构规则使用受限的变换模式，核对完整剩余子树、执行位置、访问对象、谓词、顺序及估算证据。规则版本 3 支持整树组合证明：每项记录 `requires_rules`，只有同时勾选全部依赖卡才生效；不允许单独一张卡覆盖另一张卡证明的差异。独立完整证明已覆盖的差异，不再被另一个未通过阈值的候选重复阻断；未覆盖的失败仍保留复核。

复杂 Join、访问路径、窗口及截断取舍可以由 A22 的共同工作量模型单独评分，结果明确标记为“估算模型预判”，与结构证明区分。未知算子、引擎、无界列宽、统计不可靠、相关扫描估算口径异常等情况拒绝评分；不能通过模型消除 CAST 类型语义冲突。

| A03 回表前过滤 | 相同索引及确定性整数比较谓词，从 TableRowIDScan 上方移动到索引扫描上方 | 减少回表候选预判变优，反向变差 |

| E10 冗余 Limit | 外连接内侧唯一聚簇主键匹配，外侧已内嵌相同 Limit | 顶层重复截断增删基本等价 |

| E12 排序权重展示 | SQL 显式 general_ci、ASCII 等值端点与 UTF-16 大写权重编码逐字对应 | 基本等价；不泛化到所有 Unicode/collation |
| E14 长绑定常量 | 完整字符串与旧计划相同，新计划精确匹配前 64 字节及总字节长度 | 基本等价；相同前缀和长度不足以单独放行 |
| E15 ShuffleReceiver | 相同 Shuffle 并发及 Window/Sort/输入，仅显式增加接收边界 | 基本等价 |

A03/A06/A08/A09/A11/A12 需要同源统计就绪、无 `stats:pseudo` 或 `stats:partial`，并且当前只使用可确认的单表查询材料。数值比较使用十进制精确值，浏览器使用整数分数运算，不用浮点舍入放宽边界。

| 策略参数 | 默认值 | 范围 |
|---|---|---|
| 下推最小输入行数 | 1000 | 1–1000000000 |
| TopN / Limit 最大 `(offset+count)/输入` | 10% | 1–50% |
| 过滤至少减少 | 50% | 1–99% |
| E05 `max(estRows)/min(estRows)` 容差 | 10% | 1–50%，默认不启用该卡 |

A12 还要求输入至少 10000 行、中间行比例不超过 10%，调整通用阈值不能放宽这两个上限。阈值是 PCC 的保守策略，不是 TiDB 官方保证；局部 TopN 的 K 也不是整个集群最终只传 K 行。

聚合按 TiDB 的实际 partial/final 展示识别：COUNT 的最终节点是 `count(Column#...)`，不是 SQL 代数改写的 SUM。规则版本 2 修正了该识别，并保存 v6.5.12 / v8.5.5 的真实计划作为回归夹具。

### A22 的模型与限制

A22 使用 DDL 有界最大列宽；不猜测 TEXT/BLOB 的平均宽度。权重为扫描字节 ×1、回表字节 ×4、传输字节 ×0.5、CPU 工作单位 ×8、工作内存字节 ×0.1。排序计入 `N log2(K)`（Sort 的 K=N），Join 区分构建、探测及有序合并；Index Join 内侧 estRows 按 v6.4 起的总量口径使用，不再乘外侧行数。小于一行的访问估算统一按一行计，空 TableDual 除外。每条命中保存 `basis=estimated_work` 和完整 `model`，导出保留相同证据。

这些权重、宽度近似和 1.20 容差是 PCC v1 启发式策略，**不是 TiDB 官方成本公式，也不是经过耗时标定的性能预测**。模型比较总工作量，不直接将并发数折算为耗时加速；缓存、倾斜、批次、实际列宽、溢出都可能改变方向。不能直接比较两个版本原生 estCost 来替代共同口径。只有出现受支持的物理取舍才产生候选，“没有其他规则命中”不是模型候选条件。

## 复核提示：22 类

这些卡可勾选并显示适用的复核依据，**不单独据此判优、判差或等价**。其中 A04/A05/A13–A16/A18/A19、E04 需要更丰富的范围、类型、唯一性或版本默认值证明；C01–C13 本身没有固定的优劣顺序。满足 A22 完整评分条件的复杂取舍仍可自动给出估算方向。

提示覆盖全扫描与范围访问、范围缩放、列裁剪、排序消除、MIN/MAX、聚合与 DISTINCT 消除、外连接消除、分区裁剪、窗口上界、显式默认字段，以及索引替换、Join 算法/顺序/Build-Probe、HashAgg/StreamAgg、IndexMerge、TiKV/TiFlash/MPP、Broadcast/Shuffle、Apply、CTE、并行窗口、Runtime Filter、分区模式和计算型 Projection 下推。

例如，任意 Projection 从 root 移到 cop 并不都减少传输；A07 只接受已核验版本的纯列裁剪前提。计算型投影、未知版本或 CAST 类型长度变化不能套用。换索引、换 HashJoin、启用 TiFlash 也没有“一定更快”的自动规则。

## 依据与版本边界

规则卡内提供具体来源链接。主要依据为官方[访问路径选择](https://pingkai.cn/docs/tidb/stable/choose-index)、[谓词下推](https://pingkai.cn/docs/tidb/stable/predicate-push-down)、[TopN/Limit 下推](https://pingkai.cn/docs/tidb/stable/topn-limit-push-down)、[聚合执行计划](https://pingkai.cn/docs/tidb/stable/explain-aggregation)、[列裁剪](https://pingkai.cn/docs/tidb/stable/column-pruning)。这些文档描述优化机制，PCC 的覆盖合并和阈值是本项目的规则策略。

E01 核对了 TiDB v6.5.12 / v8.5.5 源码中的 `ExplainExpressionList`；[v8.5.5 实现](https://github.com/pingcap/tidb/blob/v8.5.5/pkg/expression/explain.go#L182)在投影来源列与输出列标识不同的时候追加箭头标记。涉及聚合和连接消除的提示同时引用 v8.5.5 优化器源码。不能将更新版本文档中的新算子能力自动当作 v8.5.5 已有能力。

本轮真实数据库验证为 Community v6.5.12 → v8.5.5。新增 44 组真实升级计划夹具，逐个检查正反方向、组合规则依赖、未知输入拒绝和浏览器/Python 一致性；另有两个版本的 NTH_PLAN 聚合对照。不是全部 TiDB 版本或实测性能认证。验证结果见[验证说明](validation.md)。

## 归档

- `assessment_rules.json`：规则目录、默认选择、阈值和版本/指纹。
- `assessments.jsonl`：每条 SQL 的候选证据与默认判断；`items.jsonl` 同时保存这些字段。
- `inputs/assessment_schema.json`：仅保存解析出的列类型、聚簇主键、统计就绪和 DDL hash，供离线重算使用；纳入原有 manifest 校验。
- HTML 自带相同候选证据和判断器，点击按钮不访问数据库或外网。JSON/CSV 导出代表用户当前选中的规则，归档中的默认结果保持不变。

旧版本归档没有新增 DDL 证据时，仍可重算，但需要该证据的自动规则保持待复核。
