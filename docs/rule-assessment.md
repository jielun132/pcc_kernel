# 执行计划规则预判（0.1.6）

规则预判回答“从已采集的计划变化能否推断一个方向”。输入是同一 SQL 样例、相同参数下的普通 EXPLAIN，不执行 EXPLAIN ANALYZE，不证明实测耗时、生产性能或版本因果关系。

## 在报告中使用

报告打开时展示推荐规则的默认判断。展开“选择规则与阈值”，勾选后点击“按所选规则重新判断”。每次处理全部已确认差异、默认必审及选入运行时复核的 SQL。搜索、分页、分组及暂缓查看的库只影响浏览。

修改规则或阈值后，页面标记“当前展示上次判断结果”并暂停导出；点击重判才应用。全不选时，全部差异保持待复核。JSON/CSV 导出包含所选规则、阈值、规则版本和指纹、报告指纹、每条 SQL 的结论、命中证据及未覆盖差异。页面内修改不会写回原始归档，重新打开 HTML 恢复生成时的默认结果。

原始比较状态和退出码分别记录在报告中。命中默认必审卡或所选运行时卡时，即使原始计划一致也进入待复核。未运行的样例保留其拦截或缺样原因。相似计划分组不会继承或传播结论。存在非阻断的上下文差异时，保留警告，不能将结论直接归因于版本。

## 空表对计划的影响与运行时提示（D01–D13）

PCC 将表结构和统计导入测试库。统计可以描述行数与分布，却无法替优化器读出一行数据。D01/D02 识别可能在规划时提前读表的标量或存在性子查询。D08 表示性能方向仅有代价模型支持，D10 表示缺少 SQL 或视图定义。这四张卡命中即复核。另外九张卡记录运行时才可验证的因素，默认显示在详情和导出里。完整覆盖差异的结构规则仍可给出预判。勾选某张运行时卡后，命中的 SQL 才加入本次复核。每条 SQL 可命中多张卡，待复核总数按 SQL 去重。旧报告通过菜单 7 离线重算时也会检查这些条件。

| 卡号 | 检查什么 | 用有数据的隔离库复核什么 |
|---|---|---|
| D01 | 读表的标量子查询，包括投影、谓词、写入及经过 CTE 或派生表的读取 | 同一绑定下的实际常量、NULL、主键范围。可能产生多行时核对 1242 |
| D02 | 可独立求值的 EXISTS / NOT EXISTS | 内层有匹配和无匹配时，外层扫描是否消失 |
| D03 | 相关子查询、Apply、Index Join、逐外键决定的范围 | 外侧行数、重复键、内侧循环及每键匹配行数 |
| D04 | IN、NOT IN、ANY、ALL 子查询，集合相交、求差或去重 | 集合大小、重叠率、NULL 和重复值 |
| D05 | 筛选或连接后取有限行，存在过滤、排序或连接候选 | 找到第 K 个合格行前的实际扫描及回表量 |
| D06 | 计划出现 Runtime Filter | Build 键覆盖率、过滤前后行数和等待时间 |
| D07 | 计划显示动态分区扫描或由外部键决定的分区访问 | 原参数下命中的分区及各分区扫描量 |
| D08 | 净收益仅有 A22 工作量模型评分 | 真实扫描、回表、传输、内存和耗时 |
| D09 | 物化 CTE 或分区窗口 | 临时结果、高频分区、内存和落盘 |
| D10 | SQL 或依赖的视图缺少可解析定义 | 补齐定义，展开后核对是否含读表求值 |
| D11 | INSERT、REPLACE、UPDATE、DELETE | 匹配、唯一键冲突分支、实际写入量、索引维护和锁 |
| D12 | Region 采样、随机筛选或排序 | 物理 Region 布局、获取的样本、同数据多次采样的波动 |
| D13 | 不能证明单侧唯一的连接，或有扫描输入的分组、去重聚合 | 键的重复度、连接放大、实际组数、内存与落盘 |

例如 SQL-0293 使用读表的标量 MAX，经空集求值得到 NULL，外层比较可能折叠为零行。单独看到 TableDual 不会触发此卡，常量谓词 WHERE 1=0 在有数据时也没有结果。普通 IN 常量列表、单独的顶层 MAX、常量标量子查询，也不因这些写法本身触发 D01/D04。命中的业务写语句只采普通 EXPLAIN。关于提前求值和新版本会话开关，见 [TiDB 执行计划示例](https://pingkai.cn/docs/tidb/stable/explain-walkthrough)。

## 判定方式

每个候选命中记录规则 ID、方向、原始差异序号、旧新节点、前提和数值证据。只有覆盖了全部差异才允许自动分类：

| 证据组合 | 结论 |
|---|---|
| 只有变优方向，可同时含等价证据 | 变优 |
| 只有变差方向，可同时含等价证据 | 变差 |
| 全部差异均有等价证明，且没有命中必审卡 | 基本等价 |
| 未覆盖、缺少前提、阈值未满足、语义不完整或正反方向冲突 | 待复核 |

不把没有命中当作等价，也不把计划一致说成实测性能相同。结构规则使用受限的变换模式，核对完整剩余子树、执行位置、访问对象、谓词、顺序及估算证据。规则版本 3 支持整树组合证明：每项记录 `requires_rules`，只有同时勾选全部依赖卡才生效；不允许单独一张卡覆盖另一张卡证明的差异。独立完整证明已覆盖的差异，不再被另一个未通过阈值的候选重复阻断；未覆盖的失败仍保留复核。

复杂 Join、访问路径、窗口及截断取舍可保留 A22 的参考分数。结论依赖该模型时，D08 要求现场复核。未知算子、引擎、无界列宽、统计不可靠、相关扫描估算口径异常等情况拒绝评分；不能通过模型消除 CAST 类型语义冲突。

## 结构预判与工作量估算（28 类可自动预判，A22 为参考评分）

| 卡片 | 当前可证明的模式 | 正反方向 |
|---|---|---|
| A01 唯一键点查 | DDL 证明的单个整数聚簇主键，相同键值，TableReader + 单点范围扫描与 Point_Get | 改为 Point_Get 预判变优，反向变差；批量点查暂不自动判 |
| A02 覆盖索引 | 同索引、同范围、同候选数，SQL 所需列由索引及聚簇主键覆盖，无回表端过滤 | 消除回表预判变优，反向变差 |
| A03 回表前过滤 | 相同索引及确定性整数比较谓词，从 TableRowIDScan 上方移动到索引扫描上方 | 减少回表候选预判变优，反向变差 |
| A06 谓词下推 | 相同 Selection 从 root 移到直接读取的 TiKV 侧，扫描保持不变；仅整数比较及其 AND/OR 组合 | 减少传输候选预判变优，反向变差 |
| A07 传输列裁剪 | 同一纯列投影跨 Reader 下推，社区 v8.5.5 和 v8.5.7 均要求纯列输出数少于输入数 | 减少传输列预判变优，移回 root 变差 |
| A08 TopN 下推 | 保留最终 TopN，TiKV 增加相同排序键的局部 TopN；局部 offset=0、count=最终 offset+count | 提前有界截断预判变优，反向变差 |
| A09 Limit 下推 | 保留最终 Limit，在相同直接扫描端增加局部 Limit；不跨过滤或 Join | 提前截断预判变优，反向变差 |
| A10 有序 IndexMerge | 聚簇主键、单列等值索引前缀、有序输入，TopN 改为同 offset/count 的内嵌 Limit | 消除额外 TopN 预判变优，反向变差 |
| A11 有界排序 | 同排序键与 offset/count 的 Sort + Limit 和 TopN，输入子树相同 | TopN 预判变优，反向变差 |
| A12 部分聚合 | 单个无 DISTINCT/GROUP BY 的 COUNT/SUM/MIN/MAX，识别 partial/final 列映射，扫描不变 | 减少中间行传输预判变优，反向变差 |
| A17 恒假消除 | 简单 SELECT 的 WHERE FALSE、0 或确定不相等的数值常量相等条件，Selection 分支与空 TableDual | 消除扫描分支预判变优，反向变差 |
| A20 NULL 感知反半连接 | 同输入、角色、eq 条件，笛卡尔反半连接转为 Null-aware 哈希连接 | 预判变优，反向变差 |
| A21 NULL 安全哈希键 | 半连接 nulleq 从 other cond 提升为哈希键，其他输入保持一致 | 预判变优，反向变差 |
| A22 综合工作量估算 | 两端使用同一 PCC 模型，比较扫描、回表、传输、CPU 和内存；详情公开分量、权重、假设 | 列出工作量、假设和 1.20 容差，由 D08 判为待复核 |
| E01 列别名展示 | 同位置、同来源的纯列，仅增加或改变显式 `->Column#` 展示标记 | 基本等价；不删除计算表达式、未知列 ID 或列增删 |
| E02 相邻透传投影 | 两个相邻、同位置执行、完整列列表相同的 Projection 与一层 Projection | 基本等价；跨 root/cop 的移动不属于本模式 |
| E03 简单谓词展示 | 白名单中的纯整数常量比较换序及 AND 列表换序；DDL 证明的整数列 Join 等式左右交换 | 基本等价；不归一化字符串、NULL、列类型转换和任意函数 |
| E05 估算容差 | 物理计划完全相同，仅正值 estRows 在容差范围内 | 默认关闭，勾选后按策略视为基本等价；零值、缺失值不放行 |
| E06 聚合列映射 | 注入 Projection 的连续槽位、显式锚点和全部聚合引用一致，仅重复纯列或编号改变 | 基本等价；计算表达式、分组和输出变化拒绝 |
| E07 相关冗余过滤 | 外侧整数主键上界与动态等值范围已蕴含新过滤，回表候选相同 | 基本等价；不将相关叶子 estRows 的口径变化计为额外 I/O |
| E08 DECIMAL 零展示 | IF 分支零常量补足 DDL 中的 DECIMAL 小数位，其他表达式相同 | 基本等价 |
| E09 统计诊断 | 未初始化列诊断及相同扫描/谓词上的过滤、透传估算变化 | 基本等价证据，仍显示统计警告；访问路径变化需其他证明 |
| E10 冗余 Limit | 外连接内侧唯一聚簇主键匹配，外侧已内嵌相同 Limit | 顶层重复截断增删基本等价 |
| E11 版本估算下限 | 亚一行估算、空 TableDual 和透明传播，逐项核对完整物理计划 | 基本等价，保留原始估算 |
| E12 排序权重展示 | SQL 显式 general_ci、ASCII 等值端点与 UTF-16 大写权重编码逐字对应 | 基本等价；不泛化到所有 Unicode/collation |
| E14 长绑定常量 | 完整字符串与旧计划相同，新计划精确匹配前 64 字节及总字节长度 | 基本等价；相同前缀和长度不足以单独放行 |
| E15 ShuffleReceiver | 相同 Shuffle 并发及 Window/Sort/输入，仅显式增加接收边界 | 基本等价 |
| E16 相同访问上的行数估算 | DDL 确认数值列，相同的静态范围、顺序及引擎，正估算在 10% 以内。相同全表扫描后的相同整数过滤可另行核对输出估算及逐层透传 | 基本等价，保留估算变化。动态范围和缺失统计材料仍待复核 |
| E17 零行输入的分组聚合 | 两端实际计划均给出 `TableDual rows:0`，分组键、输出及投影表达式逐项相同 | HashAgg 和 StreamAgg 都处理零行，判为基本等价 |

规则 v4 区分社区 v8.5.5、v8.5.7 和平凯 v7.1.9-0.3 的版本标识。与 v6.5.12 比较时，按实际出现的计划字段、SQL、DDL 和统计证据应用规则。源码限定的投影裁剪保留社区版本条件。A22 在相同有序输入和相同 ROW_NUMBER 窗口定义下估算逐行工作，对有序多段索引与 TopN 的取舍计入归并开销。两类结果均在报告中显示模型假设。平凯文档解释了各算子显示的估算行数及索引内表的统计口径。[执行计划概览](https://pingkai.cn/docs/pingkaidb/stable/explain-overview)

A03/A06/A08/A09/A11/A12 需要同源统计就绪、无 `stats:pseudo` 或 `stats:partial`，并且当前只使用可确认的单表查询材料。数值比较使用十进制精确值，浏览器使用整数分数运算，不用浮点舍入放宽边界。

| 策略参数 | 默认值 | 范围 |
|---|---|---|
| 下推最小输入行数 | 1000 | 1–1000000000 |
| TopN / Limit 最大 `(offset+count)/输入` | 10% | 1–50% |
| 过滤至少减少 | 50% | 1–99% |
| E05 `max(estRows)/min(estRows)` 容差 | 10% | 1–50%，默认不启用该卡 |

A12 还要求输入至少 10000 行、中间行比例不超过 10%，调整通用阈值不能放宽这两个上限。阈值是 PCC 的保守策略，不是 TiDB 官方保证；局部 TopN 的 K 也不是整个集群最终只传 K 行。

聚合按 TiDB 的实际 partial/final 展示识别：COUNT 的最终节点是 `count(Column#...)`，不是 SQL 代数改写的 SUM。规则版本 2 修正了该识别，并保存 v6.5.12 / v8.5.5 的真实计划作为回归夹具。

### A22 的模型与限制

A22 使用 DDL 有界最大列宽；不猜测 TEXT/BLOB 的平均宽度。权重为扫描字节 ×1、回表字节 ×4、传输字节 ×0.5、CPU 工作单位 ×8、工作内存字节 ×0.1。排序计入 `N log2(K)`（Sort 的 K=N），Join 区分构建、探测及有序合并；Index Join 内侧 estRows 按 v6.4 起的总量口径使用，不再乘外侧行数。小于一行的访问估算统一按一行计，空 TableDual 除外。每条命中保存 `basis=estimated_work` 和完整 `model`，导出保留相同证据。

这些权重、宽度近似和 1.20 容差是 PCC v1 启发式策略，**不是 TiDB 官方成本公式，也不是经过耗时标定的性能预测**。模型比较总工作量，不直接将并发数折算为耗时加速；缓存、倾斜、批次、实际列宽、溢出都可能改变方向。不能直接比较两个版本原生 estCost 来替代共同口径。只有出现受支持的物理取舍才产生候选，“没有其他规则命中”不是模型候选条件。

## 可选复核提示（22 类，另有 A22 估算参考）

这些卡可勾选并显示适用的复核依据，**不单独据此判优、判差或等价**。其中 A04/A05/A13–A16/A18/A19、E04 需要更丰富的范围、类型、唯一性或版本默认值证明；C01–C13 本身没有固定的优劣顺序。A22 满足评分条件时展示各项估算，D08 仍然生效。

提示覆盖全扫描与范围访问、范围缩放、列裁剪、排序消除、MIN/MAX、聚合与 DISTINCT 消除、外连接消除、分区裁剪、窗口上界、显式默认字段，以及索引替换、Join 算法/顺序/Build-Probe、HashAgg/StreamAgg、IndexMerge、TiKV/TiFlash/MPP、Broadcast/Shuffle、Apply、CTE、并行窗口、Runtime Filter、分区模式和计算型 Projection 下推。

例如，任意 Projection 从 root 移到 cop 并不都减少传输；A07 只接受已核验版本的纯列裁剪前提。计算型投影、未知版本或 CAST 类型长度变化不能套用。换索引、换 HashJoin、启用 TiFlash 也没有“一定更快”的自动规则。

## 依据与版本边界

规则卡内提供具体来源链接。主要依据为官方[访问路径选择](https://pingkai.cn/docs/tidb/stable/choose-index)、[谓词下推](https://pingkai.cn/docs/tidb/stable/predicate-push-down)、[TopN/Limit 下推](https://pingkai.cn/docs/tidb/stable/topn-limit-push-down)、[聚合执行计划](https://pingkai.cn/docs/tidb/stable/explain-aggregation)、[列裁剪](https://pingkai.cn/docs/tidb/stable/column-pruning)。这些文档描述优化机制，PCC 的覆盖合并和阈值是本项目的规则策略。

E01 核对了 TiDB v6.5.12 / v8.5.5 源码中的 `ExplainExpressionList`；[v8.5.5 实现](https://github.com/pingcap/tidb/blob/v8.5.5/pkg/expression/explain.go#L182)在投影来源列与输出列标识不同的时候追加箭头标记。涉及聚合和连接消除的提示同时引用 v8.5.5 优化器源码。不能将更新版本文档中的新算子能力自动当作 v8.5.5 已有能力。

0.1.5 在 Community v6.5.12 → v8.5.5 实库上建立 44 组升级计划夹具，覆盖正反向结论、组合规则依赖、未知输入和浏览器/Python 一致性。0.1.6 增加 Community v8.5.7 实库采集，以及平凯 v7.1.9-0.3 真实记录的离线回放。[验证说明](validation.md)

## 归档

- `assessment_rules.json`：规则目录、默认选择、阈值和版本/指纹。
- `assessments.jsonl`：每条 SQL 的候选证据与默认判断；`items.jsonl` 同时保存这些字段。
- `inputs/assessment_schema.json`：保存解析出的列类型、聚簇主键、统计就绪、DDL hash 及视图的数据依赖特征，供离线重算使用；纳入原有 manifest 校验。
- HTML 自带相同候选证据和判断器，点击按钮不访问数据库或外网。JSON/CSV 导出代表用户当前选中的规则，归档中的默认结果保持不变。

旧版本归档没有新增 DDL 证据时，仍可重算，但需要该证据的自动规则保持待复核。
