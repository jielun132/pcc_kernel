核心比对逻辑与规则口径
  1. 先校验是否能完整比较。材料、参数、计划解析或必要上下文不足时归入“无法比对”，不会计入差异 SQL 数。
  2. 按计划树局部匹配节点。在对应父节点的子节点内，依次尝试完整子树、对象＋算子＋属性、完整后代子树（保留谓词、忽略估算行数）、访问对象、算子＋角色、算子；每步只采用双方唯一的对应。最后只剩一对时局部配对。单子节点包装层增删单独识别。仍有歧义时保留观察并要求复核。
  3. 保留算子语义。统一 row / JSON 列名、数值格式和已知算子临时编号及引用；不把 FullScan 与 RangeScan、HashJoin 与 MergeJoin 合成同一种算子。当前没有未经验证的跨版本算子等价映射，未知算子或字段按无法完整比较处理。
  4. 比较属性并归并事实。比较具体算子、表/索引/分区、任务与引擎、Join 角色、子节点顺序、谓词属性和 estRows。同一 SQL 同一访问位置的扫描、父级链路及对象变化归并，保留规则及全部字段证据；其他位置分别计数。估算行数单列为辅助指标。
  5. 相似分组只辅助浏览。按差异类别、规则及旧新算子结构分组，不以表名、谓词或估算数值决定相似；每条 SQL 的数据规模、分布及业务场景仍需 DBA 单独复核。没有批量通过或结论继承。

规则版本 1。规则识别事实，不给出性能优劣或自动批准结论。仅 estRows 变化也属于“存在差异”，但只计入辅助指标，不计入访问路径等计划事实项。
